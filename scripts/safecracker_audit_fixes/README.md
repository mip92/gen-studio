## Ловушка, на которой я попался дважды

1. **Чиня один тик, легко завести другой.** Пять «девять лет» я заменил на пять
   «четыре года» и получил ровно тот же фразовый тик с другим числом. §1 поймал
   это на следующем прогоне. Перепроверять аудитом ПОСЛЕ каждой правки, а не
   один раз в конце.
2. **`PATCH /shots/:id` не принимает `shotType`** — в DTO его нет. Он молча
   обновил `promptFields` и оставил колонку прежней, а по колонке считается
   чередование масштабов (§5.1). Колонка правится SQL (`06_*.sql`), и после
   любой смены вводного слова надо сверять три места: колонку,
   `promptFields.camera.shotType` и первую клаузу `positive`.

## Порядок применения

```
python scripts/safecracker_audit_fixes/01_narration_forbidden_words.py
python scripts/safecracker_audit_fixes/02_prompts_negations_stance.py
python scripts/safecracker_audit_fixes/03_last_stance_and_location.py
python scripts/safecracker_audit_fixes/04_chronology_and_continuity.py
python scripts/safecracker_audit_fixes/05_phrase_tics_and_shottype_runs.py
psql -f scripts/safecracker_audit_fixes/06_shottype_column.sql
psql -f scripts/safecracker_audit_fixes/07_act3_title_collision.sql
```

Скрипты 01–05 ходят через API на `localhost:4000` (озвучка обязана идти через
`PATCH /tts/shots/:id/narration`, §12.7a) и держат кириллицу в UTF-8 из Python —
через тело PowerShell 5.1 её слать нельзя.

## Проверка

```
psql -f scripts/safecracker_audit_fixes/audit_full.sql
python scripts/safecracker_audit_fixes/audit_mechanical.py
```

Ожидаемое состояние: запрещённые слова 0, `, и это` 0, `ровно` 0,
`потому что` ≤2, отрицания в позитиве 0, кадры без клаузы корпуса 0, дубли 0,
строки короче 6 слов 0, прогоны плана нет, межпроектные 3-граммы — только
дисклеймер и CTA, повторяющиеся 3-граммы — только лейтмотивы («садится позже»,
«семь засовов»).
